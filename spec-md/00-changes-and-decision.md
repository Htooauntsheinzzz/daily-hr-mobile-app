## 2026-11-27 — Leave management on Supabase

- **Change** — Added `supabase/migrations/20261127030000_leave_management.sql`: a `leave_types` table (Annual Leave 6 days per calendar year, Monthly Leave 2 days per month, Partial Leave unpaid with no limit and only once the others are used up), `leave_type`, `days` and `unpaid` columns on `work_requests`, a `leave_balances` table with one row per employee, type and period, and the functions `request_leave`, `decide_leave`, `cancel_leave` and `leave_balances_for`. Days are counted Monday to Friday from the start date to the end date. Annual Leave must stay within one year and Monthly Leave within one month; overlapping leave is refused; pending requests hold their days. `decide_leave` locks the request, refuses anything not Pending, and deducts the balance in the same transaction, so a repeated tap can't deduct twice. Leave can no longer be inserted or updated directly. The app loads leave types and leave requests from Supabase at sign-in and when HR opens the leave queue, shows Annual and Monthly balances with their reset rule, explains Partial Leave, and submits, approves, rejects and cancels through those functions. The same rules run on the device first for a quick answer and in demo mode; old saved "Annual leave"/"Sick leave" names map to the new types.
- **Decision and reason** — Requested by Hsu. Periods follow the calendar (Annual resets 1 January, Monthly on the 1st). The balance table plus a locked approval satisfies "update the balance and approval together". Overtime requests stay on the device for now.
- **Verification** — `flutter analyze` clean; 75 tests pass, including the new `leave_test.dart` (yearly and monthly resets, month boundary, pending holds, Partial Leave unlocking, overlap, Supabase submit/cancel, local checks before calling Supabase, double approval tap). Existing tests were updated for the new type names and allowances. iOS simulator build succeeded. SQL not run (Hsu runs it).
- **Open** — Partial Leave days are recorded as unpaid, but payroll doesn't deduct them yet; the deduction rule (for example base salary ÷ working days in the month × unpaid days) needs Hsu's decision when payroll moves to Supabase.
- **Follow-up (migration order)** — The first run failed because the existing "Annual leave" request was renamed before the old `work_requests_check` constraint (which only allowed the old names) was dropped. Supabase rolled the whole script back (confirmed read-only: no new tables or functions). The constraint is now dropped before the rename.
- **Follow-up (leave form and balances)** — The leave form now has separate Start date and End date fields instead of a range picker. Choosing a start date sets the end date to the same day, so one-day leave needs one choice; the end date can't go past the month (Monthly Leave) or year (Annual Leave), and changing the type keeps the dates valid. The form says how many days of the chosen type can still be taken. Balance cards now show what's left after approved and pending requests ("1 day left of 2"), with "N days waiting for approval" while pending. Checked the hosted project read-only: the leave migration is applied with Annual 6/year, Monthly 2/month and Partial Leave. 76 tests pass, including a widget test that submits one day of Monthly Leave and sees 1 day left.
